# OPA decision identifier producer conformance — frozen protocol v1

Baseline: 28c252337ea50e082d3c348680b7dbc54b0f0751.

## Objective and claim

Determine identifier generation and relationship semantics in AGG's actual stock OPA 1.19.0 `exec --stdin-input --bundle ... --decision /agentgov/complaints/decision --set=decision_logs.console=true --log-format=json` integration. Under this archived configuration, the output decision_id is generated by OPA rather than copied from caller input, agrees with the native console decision-log ID for that evaluation, and is distinct across the finite repeated evaluations tested. The output/log pair is two representations of one evaluation, not two independent corroborations. An execution's recorded ID alone does not establish execution, caller authentication, enforcement, or target outcome.

## Frozen experiment

Use the existing openpolicyagent/opa:1.19.0 image and existing policies, record resolved image identity and version, and mount the policy bundle read-only. No network target, production systems, credentials, model, or new framework is needed. Run eight sequential separate `opa exec` invocations with one JSON input each, no automatic retries. Base input is baseline input.json. Cases 1–2: unchanged base input. Cases 3–4: base input plus top-level decision_id = CALLER-SAME. Cases 5–6: base input plus decision_id = 00000000-0000-4000-8000-000000000000 and nested user.decision_id = CALLER-NESTED. Cases 7–8: base input plus decision_id = CALLER-DENY and authorized_resource_ids = []. Repetition within each pair is exact. All extra fields are input data, not SDK options.

Freeze protocol, runner, tests, configuration/policy/input hashes and all baseline tracked-file hashes before evaluations. Record invocation arguments, exact input bytes, stdout/stderr bytes, exit code and observation times separately for each invocation. Associate output/log by process custody and single-evaluation cardinality, never by ID equality. Native records must remain unmodified. Refuse existing capture directories. Retain partial/failed campaigns and never silently replace or resume them. Infrastructure corrections may create a separately named campaign only if no completed evaluation exists; otherwise preserve results and stop for review if changing protocol is necessary.

## Checks and decision rules

Each invocation must exit zero and emit exactly one result and one native decision-log event. Both IDs must be nonempty UUID-format strings, agree, and differ from every supplied caller-ID sentinel. Native logged input must equal submitted input; native/output policy results must agree and match expected ALLOW (1–6) or DENY (7–8). All eight native IDs must be distinct. Preserve duplicates as observations; do not claim input caused a random collision. Source review must trace stock exec ID generation and absence/presence of caller override to version-pinned upstream source.

Incomplete capture, ambiguous cardinality, unavailable runtime/source, configuration mismatch or unresolved check: NOT_EVALUABLE. Complete evidence demonstrating caller-ID substitution or output/log mismatch: PRODUCER_CONTRACT_CONTRADICTED. Complete evidence with observed duplicate generated IDs: PRODUCER_CONTRACT_CONTRADICTED for the finite distinctness claim, without claiming copying or general collision rates. All runtime checks and source review supported: PRODUCER_CONTRACT_SUPPORTED, limited to the captured configuration and cases. Other semantic mismatches: NOT_EVALUABLE with explicit reason. Report per-check results as well as overall verdict. Unit fixtures test evaluator behavior and are not empirical producer evidence.

## Source and repository review

Use official OPA documentation and version-pinned source to distinguish stock exec, stock REST, and SDK/custom-runtime DecisionID options. REST/SDK are a source-review comparison, not empirically tested integration claims. No live REST or custom SDK campaign is required or authorized by this protocol. Identify actual AGG call sites and whether raw retention, normalized IDs and invocation/configuration provenance distinguish stock and custom origins. Recording a returned ID links a caller's report to an evaluation only conditional on trustworthy custody and producer semantics; it does not independently bind that evaluation to subsequent execution or an authenticated caller. Make these limits explicit.

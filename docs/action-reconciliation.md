# M6: governed, executed and target-observed action reconciliation

M6 adds a derived, reviewable assertion over separate governance, execution and target evidence. It preserves source identities and observations. It does not alter OPA policy, M4 temporal authority, M5 delegation, the deterministic matcher, correlation assertions, or the legacy runtime reconciler.

## Bounded claim

The controlled complaint experiment demonstrates a real OPA governance decision, a real HTTP request and an independently produced stock NGINX access record. Agent Gov Graph consumes the native target record after NGINX stops, replays existing correlation assertions, and identifies a DENY/target-effect contradiction without inventing client success. Independence here means a separate producing process and writing path, not an independent organization, independently administered host, or authenticated forensic chain of custody.

The existing complaint store and M3 `OBSERVED_OUTCOME` events are runtime-authored. They remain runtime claims; they are not upgraded to independent target evidence.

## Source contracts

`action_evidence.schema.json` describes envelopes with role, original raw record, stable evidence reference, original-file digest, relative archive member, line number, byte offset/length and line digest. Ingestion time is separate from observation time. Missing/malformed fields become explicit defects. An entire file is a captured snapshot: appending changes file identity; repeated ingestion of unchanged bytes preserves references. Digests establish supplied content identity, not authenticity.

* Governance retains the original event, actor in the `agent` namespace, proposed action/resource, policy decision, original event-recording time, `authority_resolution_at`, and OPA native decision time. The OPA time is the governance observation time. They are not interchangeable.
* Execution retains the runtime actor, submitted action/resource, request observation time, submission disposition, nullable client success, response status, failure stage, runtime action-attempt ID and the **response-side server-issued NGINX request ID**. The raw receipt also preserves received body-byte count. A submitted request is not client success. Client failure or absent success is not proof that no target effect occurred.
* Target evidence retains NGINX's native method, exact request URI, status, body bytes, completion indicator, native request ID, request/completion timing and Basic-auth username. Interpretation refers to an explicit, preserved static-target contract. Original records are never rewritten.

For this target only, `REPRESENTATION_SERVED` requires all of:

1. GET of an exactly mapped complaint URI, including no unrecognized query suffix;
2. the configured Basic-auth-protected static location and a nonblank native username;
3. HTTP 200, NGINX `$request_completion == "OK"`, and positive `$body_bytes_sent`;
4. well-formed native numeric/time fields.

A nonblank username alone does not establish authentication: NGINX can record a supplied username on a failed request. The successful protected GET/200 is essential. HEAD, 201, 401, unmapped resources, incomplete requests and zero bytes never establish this effect. These negative interpretation cases are fixture-tested; the preserved live run contains only the two positive GET requests.

This establishes **server-reported completed representation transmission**. It does not prove client receipt, parsing, use, external disclosure, database mutation or generic HTTP success as an effect. `NO_REPRESENTATION_ESTABLISHED` is lack of this positive claim, not proof of absence of effects. NGINX's preserved configuration, image digest and operator-declared resource mapping are part of the interpretation assumptions.

## Identity and correlation

Basic-auth identities occupy `nginx-basic:complaints-static-v1`; identical text does not equate them to runtime agents. An explicit versioned mapping is preserved and hashed as comparison evidence. Mapping never enters candidate selection, changes raw identities, supplies roles, or becomes authority evidence. Ambiguous mappings remain unknown.

The primary paths use existing native correlation assertions:

* governance ↔ execution: existing runtime `action_attempt_id`, in its declared runtime issuer namespace;
* execution ↔ target: NGINX `$request_id`, generated by NGINX, recorded in its log and returned in `X-Request-ID`.

M6 does not generate a new cross-system ID. The client never sends a chosen NGINX ID. Each accepted link must satisfy the unchanged mutually unique candidate rule. Issuer namespace/non-reuse are declared assumptions, not cryptographically proven facts.

Every supplied assertion is schema/hash checked and **replayed with the existing correlation method against the full supplied role populations**. Changed content, invented linkage, unsupported methods, or hidden competing records within that snapshot fail explicitly. The wrapper also understands existing composite assertion source labels; it does not change their field requirements. The primary experiment uses native assertions, not a newly relaxed composite match. The new namespaced actor envelopes are not implicitly flattened into legacy composite actor strings.

Reconciliation follows only explicit accepted edges, and preserves the assertion IDs forming each path. Transitive G–E–O support is shown as a path, not represented as a separately proven G–O link. Multiple connected competing action claims are insufficient evidence. Contradicted/ambiguous correlation is not upgraded into an action/outcome contradiction. Scope remains the supplied snapshot; omitted evidence outside it can still undermine linkage.

The execution-withheld view retains original files but withholds all execution records from analysis. Governance has no known common native identifier with NGINX, so there is no accepted path: the result is `INSUFFICIENT_EVIDENCE`. A separate fixture establishes the conditional rule that a genuinely accepted G–O link can support a DENY/outcome contradiction even without execution evidence. **That direct G–O linkage was not demonstrated live.**

## Comparison and result semantics

Actor, action, resource ID and resource type are compared independently for each linked pair. The assertion records both values and `SAME`, `DIFFERENT` or `UNKNOWN`; source values are never replaced. Governance decision, submission disposition, nullable client success and target-effect claim remain separate in `claims`, with specific issue codes for incompatible combinations.

| Result | Meaning |
| --- | --- |
| `CONSISTENT` | Supported claims agree within the stated scope; or bounded absence is consistent with blocking. |
| `EXPLAINED_DIVERGENCE` | Actor difference has independently verified, relevant historical delegation bases; other required evidence agrees. |
| `UNEXPLAINED_DIVERGENCE` | An observed difference remains unexplained on sufficient supplied evidence; this is not an unauthorized-behavior finding. |
| `CONTRADICTION` | A linked DENY conflicts with submitted execution or the governed target effect, or execution explicitly claims NOT_SUBMITTED while the linked target reports the effect. |
| `INSUFFICIENT_EVIDENCE` | Missing/unlinked outcome or execution, correlation ambiguity, unknown identity mapping, missing explanation evidence, or inadequate coverage prevents the requested conclusion. |
| `NOT_EVALUABLE` | Invalid source evidence, unverifiable/rehashed correlation assertion, invalid governance claim, or another input defect prevents evaluation. |

A supported contradiction is retained alongside evidence gaps: missing execution does not erase a truly established direct G–O contradiction. Conversely, unknown linkage cannot be bypassed by a tempting target record. Resource/action mismatch remains explicit divergence; it is not silently treated as the exact denied effect. Client finalization failure plus server transmission is compatible, not an execution/outcome contradiction.

## M4/M5 explanations

Actor divergence can be explained only by replaying the original M4 governance binding and a standalone M5 query for the executing actor and exact executed tuple against preserved, digest-verified authority/delegation revisions. Its authority revision must equal the governance revision. There is no current-registry or embedded-snapshot fallback.

M5 is evaluated at both M4 times. A changed supporting basis set produces `TEMPORAL_BOUNDARY_AMBIGUITY` and an insufficient explanation; neither clock is silently preferred. Native NGINX timing is separate and cross-system synchronization is not established.

Only valid delegated paths rooted in the governed actor's bound authority records explain that actor difference. An executing actor's unrelated direct authority is not evidence of delegation from the governed actor. All relevant valid bases are preserved. A defective unrelated path does not poison valid bases, and no scopes are merged or preferred. M5 permission means explicit scope membership, not OPA authorization. It cannot override DENY or excuse action/resource differences. Missing/conflicting evidence stays distinct from a known invalid path or NOT_PERMITTED.

The live run has no actor divergence. Delegation explanations, competing valid bases and historical boundary cases are deterministic test coverage, not new live delegated-enforcement experiments.

## Coverage

`observation_coverage.schema.json` records interval, precise actor/action/resource scope, separate execution/outcome capture states, and the declaration's basis. The bounded negative conclusion requires both channels captured and the decision inside the interval. Missing files are errors, not empty observations. Coverage is an operator declaration with documented limits, not a universal completeness proof.

DENY with no observed execution/outcome in the declared interval yields `CONSISTENT_WITH_BLOCKING` within a `CONSISTENT` assertion. It does **not** prove blocking occurred. Without adequate scoped coverage the result is insufficient. The live unrestricted blocked view remains insufficient because it has neither an accepted target link nor the bounded coverage declaration.

## Implementation and compatibility

New read-only adapters and `src/action_reconciliation.py` are separate from the legacy reconciler. The sole existing runtime change is an optional executor parameter behind the same governance/authority gate, defaulting to the original complaint store. `governed_action` still has no enforcement bypass. The experiment uses the already-existing explicit test bypass in `_governed_action`; it does not weaken normal enforcement or add delegated enforcement.

New schemas and result files are additive. Historical M1–M5 artifacts, seed authority archive and algorithms remain unchanged. No database, graph, new policy engine, model call, agent framework, new authority semantics or later-milestone interpretation is introduced.

## Falsification and limits

The current claim would fail if the target log were client/AGG-authored; the native ID were generated/copied into requests by the harness; logs/config did not support the narrow effect; credentials or identities were implicitly equated; an ambiguous or omitted-population link were accepted; a withheld client record were fabricated; client failure were treated as proof of no target effect; or current authority replaced preserved evidence during replay.

Repeated/reused/copied native IDs, incomplete populations, unauthenticated logging custody, incorrect identity mappings, clocks crossing authority boundaries, and incorrect target interpretation remain potential failure boundaries. The experiment demonstrates behavior under cooperative synthetic inputs and a stock target process. It does not measure enterprise false-link rates, establish malicious tamper resistance, attribute the cause of a bypass, assess a control, or prove remote recipient behavior.
